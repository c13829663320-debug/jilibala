架构类 Architecture

为什么后端选 Fastify，而不是 Express / NestJS？
  • 性能与开销：Fastify 内置基于 Schema 的 JSON 序列化（fast-json-stringify），高并发下序列化开销显著低于 Express，常驻内存也更小。
  • 原生 WebSocket：通过 @fastify/websocket 插件与 HTTP 路由同生命周期管理房间连接，省去额外 ws 服务进程。
  • 插件化 + TypeScript：依赖注入、钩子（hook）、装饰器开箱即用，结构比 Express 更规整，又不像 NestJS 那样引入过重的框架抽象。
  • 工程适配：与 Node 20+、undici、ESM 配合良好，tsx watch 热重启开发体验好，契合本项目 monorepo 快速迭代节奏。
WebSocket 多人实时的扩展性如何？单机撑不住怎么办？
  • 房间化隔离：连接按"房间/场景"分区，状态只在房间内广播，天然避免全局广播风暴。
  • 无状态横向扩展预留：接入层可水平扩容，房间状态与广播后续可切换到 Redis Pub/Sub 做跨节点转发。
  • 语音走 WebRTC：实时音视频用 WebRTC/媒体中继，不占用 WebSocket 信令带宽，信令通道只传位置/动作/出牌等小包。
  • 降级策略：WebSocket 断线自动重连 + 状态快照重拉，弱网下退化为轮询，保证玩法可恢复。
用 node:sqlite 做存储够吗？为什么不上 PostgreSQL / MySQL？
  • 数据规模匹配：本项目是社交玩法原型，核心数据是用户、房间状态、XP、场景草稿，写并发以"房间"为单位，单文件 SQLite 足够。
  • 零运维：node:sqlite 内嵌、随进程启停，无需独立数据库实例，契合 PWA / 一键部署目标。
  • 事务与一致性：单写者事务保证房间结算（如法庭出牌、XP 入账）的原子性，满足玩法正确性。
  • 演进路径清晰：数据访问层已封装 repository，规模上来后可平滑迁移到 Postgres，对上层业务透明。

部署类 Deployment

能否 Docker 一键部署？
  • 单镜像打包：前端 Vite 构建产物 + Fastify 后端打进同一镜像，容器内一并托管静态资源与 API，对外只暴露一个端口（默认 8787）。
  • 环境变量注入：Tripo / StepFun / Evomap 的 Key 通过 .env 或容器环境变量注入，不进镜像。
  • 卷持久化：SQLite 文件与上传的照片/3D 化身挂到 named volume，容器重建不丢数据。
  • 一条命令：docker compose up -d 即可起全栈，无需手动分前后端启动。
HTTPS 怎么解决？WebSocket 必须 wss 吗？
  • 浏览器强约束：PWA 与 WebRTC 要求安全上下文，生产环境必须 HTTPS，对应 WebSocket 升级为 wss://。
  • 反向终端：前面挂 Nginx / Caddy 终止 TLS，自动签发 Let's Encrypt 证书，再反代到容器 8787。
  • 开发环境：本地用 Vite dev server + 自签证书，或 ws:// 明文联调，不影响生产。
能否离线 / 内网部署？
  • 前端 PWA 离线：vite-plugin-pwa 预缓存壳与静态资源，无网也能打开广场与本地缓存场景。
  • 后端可内网自托管：Fastify + SQLite 完全本地化运行，不依赖公网。
  • AI 能力分级：联网时走 Tripo/StepFun 在线生成；离线时降级到内置规则与本地缓存 NPC 对白（见 AI 类）。

AI 类 AI Capabilities

Tripo（3D 生成）和 StepFun/Evomap（LLM）的成本如何控制？
  • 结果缓存复用：同一照片/同一场景描述的生成结果按哈希缓存，命中直接返回，不重复调用付费 API。
  • 模型分级路由：日常 NPC 对话用低成本 flash 模型（step-3.5-flash / evomap-deepseek-v4-flash），复杂造场景才升级。
  • 3D 生成按需触发：照片转 3D 是用户主动动作，不在在线路径上批量跑，按量付费可控。
  • 配额预算：服务端对每个 Key 设月度预算与用量告警，超限自动熔断。
高并发下 LLM / 3D 生成怎么做限流？
  • 令牌桶限流：按用户 + 按 Key 双层限流，防止单用户刷爆额度。
  • 队列 + 异步：3D 化身生成进入任务队列，前端轮询/WebSocket 推送进度，不阻塞实时玩法。
  • 并发上限：对外请求走 undici 连接池，控制到上游的最大并发，避免触发服务商 429。
  • 降级兜底：被限流时返回预置 NPC 对白模板，保证玩法不卡死。
离线或 AI 接口挂了，系统怎么降级？
  • NPC 对白降级：在线时用 LLM 实时生成；不可用时切到"人设剧本库 + 规则模板"，名人仍能按性格接话。
  • 玩法判定降级：法庭天平、知识擂台等结算仍走本地确定性规则，不依赖大模型。
  • 造场景降级：无法在线生成时，提供官方预制场景模板供用户选择。
  • 前端提示：界面明确标注"当前为离线/降级模式"，不假装在线生成。

性能类 Performance

3D 场景加载慢怎么办？
  • 模型压缩：glTF-Transform + draco3d + meshoptimizer 压缩 glTF，几何体减面与 Draco 解码。
  • 按需加载：广场是常驻轻量场景，六座建筑用 Suspense + React.lazy 按进入时才加载。
  • 预取与缓存：热门建筑模型浏览器端缓存，WebP/KTX2 纹理降体积。
  • 加载兜底：加载期间用对应宣传图静帧占位，避免白屏。
大模型调用延迟高，怎么缓存？
  • 语义缓存：相似问题/话题缓存命中历史回答，缩短首字延迟。
  • 流式输出：LLM 走 SSE/流式，边生成边推给前端，体感延迟大幅下降。
  • 预热：演示/高峰前预热连接池与常用人设提示词。
低端设备 / 手机跑不动 Three.js 怎么办？
  • 画质分级：按设备 GPU/帧率自动降分辨率、关阴影与后处理辉光。
  • 实例化与 LOD：名人光点用 InstancedMesh，远景降模型精度。
  • PWA 轻量壳：手机优先轻量模式，3D 简化但玩法完整。

安全类 Security

CORS 怎么配？前后端跨域会不会有问题？
  • 白名单：@fastify/cors 只放行已知前端域名，不直接 *。
  • 同源部署：生产环境前后端同源（Fastify 托管静态产物），从根本上消除跨域。
  • 凭证策略：如需带 Cookie，明确 credentials:true 并配合具体 Origin，不用通配。
第三方 API Key（Tripo/StepFun/Evomap）怎么管理？
  • 绝不落前端：所有 Key 只在后端环境变量（.env / 容器 Secret），前端永远接触不到。
  • .gitignore：.env 已被 gitignore，仓库只保留 .env.example 空模板。
  • 最小权限 + 轮换：按服务商开通最小权限子 Key，定期轮换，泄漏可单独吊销。
用户照片与个人数据怎么保护？
  • 最小收集：照片仅用于生成 3D 化身，不做无关用途。
  • 上传校验：服务端校验文件类型/大小，禁止可执行内容，落盘前清洗元数据。
  • 用户可控：提供删除入口，删除即清理对应 SQLite 记录与生成文件。
  • 注入防护：自然语言造场景的用户输入做转义，作为 LLM 提示词时隔离系统指令，防提示注入。

运维类 Operations

SQLite 数据怎么备份与恢复？
  • 定时快照：用 .backup 或文件级定时拷贝做冷备，保留多版本。
  • 卷即备份：Docker named volume 可整机快照，迁移到新容器即恢复。
  • 恢复演练：定期在测试环境做恢复演练，确认备份可用。
有没有监控告警？
  • 进程级：Fastify 暴露健康检查路由与基础指标（QPS、房间数、WS 连接数）。
  • 外部依赖：监控 Tripo/LLM 调用成功率与延迟、429/超时率，异常告警。
  • 资源：容器 CPU/内存/磁盘水位告警，SQLite 文件体积监控。
升级和回滚怎么做？
  • 镜像不可变：每次发布打版本镜像，回滚即切回上一版 tag。
  • 迁移可逆：Schema 变更写在迁移脚本并保留回滚语句，避免单向升级锁死。
  • 蓝绿/滚动：容器滚动更新，异常立刻切旧版本，数据卷不动。
