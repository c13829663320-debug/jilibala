# 叽里呱啦 BalaBala — 非法庭场景玩法诊断与重构方案

> 诊断范围：中央广场、场景工作室，以及脱口秀 / 狼人杀 / 酒吧辩论 / 健身房 / 图书馆五个建筑场景。
> 诊断基于真实源码逐文件阅读，引用函数名与关键逻辑。法庭场景由另一团队诊断，本文不覆盖。

---

## 一、广场层诊断（中央广场）

### 现状（代码证据）

**`Plaza3D.tsx`**：
- 六座建筑以环形布局摆放在 `PlazaScene` 中（`buildingPlacements` 数组，Talkshow / Werewolf / Bar / Gym / Library / Studio 各占一个角度位置）。
- 点击建筑的逻辑在 `Building` 组件的 `onClick`：直接调用 `onEnter(building.id)`，跳转路由进入对应场景 Shell。
- 玩家可用 WASD 在广场地面行走（`useCharacterControls`），镜头跟随玩家 avatar。
- 远程玩家通过 WebSocket（`room=plaza`）同步位置和旋转，以 `RemotePlayer` 小人展示。
- 底部有 minimap 显示建筑点位和玩家位置。
- **没有任何建筑上的状态标记**：无"热门"角标、无"新内容"提示、无"你还差 X 步解锁"进度环、无红点。
- **广场上没有任何可交互物件**：除了六座建筑，地面上没有可拾取物、NPC、告示牌、喷泉、摊位等。
- 玩家行走纯自由移动，没有路径引导、没有引导箭头、没有"下一步去哪"的提示。

**`Plaza.tsx`**（2D 兜底广场）：
- 纯卡片网格，每张卡片显示建筑名 + 一句描述 + "进入"按钮。
- 同样无状态、无进度、无推荐逻辑。

**`RoomEntry.tsx`**：
- 进入建筑前的过渡弹窗，仅展示房间名 + "进入房间"按钮，无匹配等待、无组队、无房间内动态预览。

### 核心问题

1. **广场是一个"3D 版菜单"，不是"世界"**。玩家走进广场唯一目的是点建筑进场景，广场本身零玩法、零停留理由。
2. **零探索动机**：地面上除了建筑没有任何可交互物，走两步就没事干。
3. **零社交触发点**：看到其他玩家小人在线上走来走去，但无法打招呼、无法组队、无法查看对方身份、无法邀请同进一个场景。
4. **零进度感**：玩家在任何场景的成就/积分/等级完全不反映在广场上，建筑不会因为你玩得多而"升级"或解锁新外观。
5. **零引导**：新用户进广场后不知道先去哪、每个建筑干嘛，全靠点进去试。

### 根因

- 架构上把广场当成了路由层（`onEnter` 直接切路由），而不是一个有自身状态和玩法的"场景"。
- 没有全局玩家档案/进度系统（player profile / level / achievements），所以广场没有东西可展示。
- WebSocket 同步了位置但没有同步"行为"（举手、跳舞、发快捷表情），社交交互停留在"看见"层面。

### 影响

- 玩家进广场后 3 秒内点进一个建筑，若那个建筑不好玩就直接退出，没有"再逛逛"的动力。
- 社交产品的"广场"本该是社交发生地，现在只是中转大厅，导致"社交"名存实亡。

## 二、场景工作室诊断

### 现状（代码证据）

**`gameplay.ts`（纯函数状态机）**：
- `createGameplayState()` 初始化三个集合：`collectedIds: Set<string>`、`reachedIds: Set<string>`、`questStatuses: Record<string, 'locked'|'active'|'done'>`。
- `applyTrigger(state, trigger)` 唯一做的事：
  - `type==='collect'` → 把 `trigger.targetId` 加入 `collectedIds`。
  - `type==='reach'` → 把 `trigger.targetId` 加入 `reachedIds`。
  - `type==='quest'` → 把对应 quest 的状态从 `locked` 切到 `active` 或 `done`。
- `checkCompletion(state, spec)` 判断"是否所有 collect/reach/quest 都完成了"，返回 `{completed, progress, total}`。
- **没有失败状态、没有计时器、没有敌人、没有伤害、没有分数、没有难度曲线、没有分支选择**。trigger 一旦触发就是永久完成，不可撤销。

**`SceneRunner.tsx`（3D 运行时）**：
- 玩家 avatar 在场景里 WASD 行走，碰到 `triggerBox`（碰撞盒）就调用 `applyTrigger`。
- NPC 站在原地，玩家走近可按 E 键对话（调用 `/api/scene-studio/npc-chat`）。
- UI 上显示一个进度条（`progress/total`）和"完成"toast。
- **没有时间压力、没有物理挑战（跳跃/躲避）、没有对抗、没有资源管理**。玩家走路→碰盒子→盒子消失→进度+1，如此重复直到走完。

**`SceneStudio.tsx`（AI 创建场景）**：
- 用户输入自然语言描述 → POST `/api/scene-studio/generate` → 返回 `SceneSpec`。
- 生成结果预览后可"试玩"。

**`scene-planner.ts`（AI 规划器）**：
- LLM 根据用户描述生成 `SceneSpec`：选 objects（从模型库挑）、放 npcs、设 spawn、设 gameplay。
- `gameplay` 字段只能是 `collect` / `reach` / `quest` 三种之一，且参数只有 `target`（目标物 id）和 `goal`（一句描述文字）。
- **AI 没有能力生成任何"挑战型"玩法**——模板库就这三种。

**`scene-routes.ts`**：
- API：`/generate`（生成场景）、`/scenes`（列出我的）、`/scenes/:id`（获取）、`/publish`（发布到广场）。
- 没有"游玩记录/评分/点赞"接口，发布出去的场景没人能给反馈。

### 核心问题

1. **Gameplay 模板是"触发器打卡器"**：collect = 走过去碰一下，reach = 走过去碰一下，quest = 走过去切个状态。三者本质相同，都是"走到 A 点→标记完成"。
2. **零挑战**：没有失败可能、没有时间限制、没有障碍物、没有需要反应的操作。玩家走路慢也能通关。
3. **零爽点**：完成一个 collect 只弹一个 toast，没有粒子特效、没有音效、没有连击、没有分数跳字。
4. **NPC 互动浅**：NPC 对话是一次性 LLM 问答，对话内容不影响 gameplay 状态，问完就走。
5. **生成端与游玩端脱节**：AI 规划器再聪明，也只能塞进三种模板里，生成出来的场景千篇一律"走到宝箱处→收集→走到终点→完成"。

### 根因

- `gameplay.ts` 的状态机设计之初就只考虑了"目标达成"（achievement），没有考虑"挑战/对抗/资源"维度。
- `SceneSpec` schema 里 gameplay 是一个有限枚举，扩展需要改 schema + planner prompt + runner 三处。

### 影响

- 玩家用 AI 生成一个场景，进去走一圈 30 秒就完了，没有重玩理由。
- UGC 创作平台的核心是"别人做的场景好玩我才来玩"，但模板太简单导致创作者做不出好玩的东西，形成恶性循环。

## 三、脱口秀场景诊断

### 现状（代码证据）

**`talkshow-orchestrator.ts`**：
- `startShow()`：选定一位主持名人，自动生成 3-5 段开场笑话，按时间间隔依次播出。
- `tellJoke()`（观众上台讲笑话）：把玩家输入的笑话发给 LLM，让 AI 观众生成"反应"（哄堂大笑 / 尴尬沉默 / 鼓掌），返回一个 `rating`（roast / applaud / mixed）。
- **演出是自动播放的**：host 讲笑话→观众反应→host 再讲→循环。玩家不点任何东西演出也会继续。
- 玩家唯一主动操作：点击"上台讲笑话"按钮，输入一段文字，得到一个观众反应评价。
- **没有多段式演出结构**（如热身段→主秀段→开放麦段），没有连续挑战。
- **没有分数累积**：讲完一个笑话得到一次 reaction，下一个笑话从头开始。

**`TalkshowShell.tsx` / `TalkshowView.tsx`**：
- 左侧显示演出时间线（笑话列表 + 观众反应 emoji），右侧 3D 舞台。
- "上台"按钮触发一个输入框，提交后等 LLM 返回 reaction。
- 讲完就完了，没有"再来一个冲击高评分"的循环。

### 核心问题

1. **玩家是观众，不是演员**。演出 90% 时间是 AI 主持在自动讲，玩家只是旁听。
2. **上台讲笑话是一次性体验**：讲一个→得到评价→结束。没有连续 3 个笑话冲"今日开放麦冠军"这种结构。
3. **反馈维度单一**：只有 roast/applaud/mixed 三档文字，没有笑声分贝条、没有观众起立鼓掌特效、没有"炸场时刻"。
4. **零重玩动机**：讲完一次就没了，下次进来还是 AI 主持讲同样套路的笑话。

### 根因

- Orchestrator 设计成了"AI 脱口秀演出播放器"，玩家是 audience seat。
- "上台"被做成了一个旁支彩蛋，而不是核心循环。

### 影响

- 玩家点进来听 AI 讲笑话，笑了一下，然后呢？没有然后。留存极低。

## 四、狼人杀场景诊断

### 现状（代码证据）

**`werewolf-orchestrator.ts`**（五场景中玩法最完整）：
- 完整的游戏状态机：`lobby → night → day_discussion → day_vote → night → ... → game_over`。
- 角色分配：狼人、预言家、普通村民（`assignRoles`）。
- 夜晚阶段：狼人刀人（AI 狼人自动商量）、预言家验人（AI 预言家自动验）。
- 白天阶段：轮流发言（AI 角色自动发言，每人一段），最后投票放逐。
- 玩家被分配一个角色，在自己发言轮次输入发言文字，在投票轮次选择投票对象。
- **胜负判定**：狼人全部出局→好人胜；狼人数量≥好人数量→狼人胜。`checkWinCondition()`。
- **AI 自主行动占比极高**：夜晚狼刀是 AI 自己决定的，白天大部分发言是 AI 轮流自动说，投票也是 AI 自动投。玩家只在"轮到你发言"和"轮到你投票"时被打断要求输入。

**`WerewolfShell.tsx` / `WerewolfView.tsx`**：
- 顶部显示当前阶段（夜晚/白天/投票）、剩余天数。
- 中间是讨论日志（滚动消息流）。
- 底部在玩家行动时显示输入框 / 投票按钮。
- 玩家不操作时，AI 自动推进，日志自动滚动。

### 核心问题

1. **玩家是"7 个 AI 中的 1 个"，但 80% 时间在看 AI 互相辩**。发言轮次中 AI 一个接一个说，玩家要等很久才轮到自己一次。
2. **玩家的发言没有结构化输入**：只能自由文本，没有"指控/辩解/跳预言家/带人"等快捷动作牌，降低了策略深度。
3. **夜晚阶段玩家完全无事可做**：好人夜晚闭眼，只能等天亮。等待时间长且无信息。
4. **无评分/段位**：赢了赢了就赢了，没有"本局表现分"、没有 KDA 式的统计、没有和其他真人玩家的段位对比。
5. **AI 发言质量参差**：AI 村民经常说"我觉得 X 是狼"但不给理由，或者理由重复。

### 根因

- 游戏原型照搬了真人狼人杀流程，但真人局里每个人都有发言欲和社交压力；AI 局里玩家变成了观众。
- 没有为"单人 vs AI"这个模式做专门的节奏压缩——真人局等 10 个人发言正常，AI 局让玩家等 6 段 AI 发言就太磨人。

### 影响

- 这是五个场景里唯一有胜负感的，但等待 AI 自动播放的时间太长，玩家容易中途退出。

## 五、酒吧辩论场景诊断

### 现状（代码证据）

**`bar-orchestrator.ts`**：
- 选择一个辩题（如"外卖是否毁掉了年轻人做饭能力"），分成正方/反方两位名人 AI。
- AI 双方自动轮流发言（`runDebateRound`），每轮 3-5 个回合。
- 玩家可以点击某位名人"点名让他说"（`callOnSpeaker`），或者投票给正方/反方（`vote`）。
- 玩家也可以选择加入一方，自己说一段（`playerSpeak`）。
- **没有辩论胜负判定**：打完若干轮就结束，没有"哪方赢了"的裁决，没有裁判角色，没有评分。
- 没有时间限制，没有回合上限硬性约束。

**`BarShell.tsx` / `BarView.tsx`**：
- 左侧显示辩题、双方队伍、当前票数。
- 中间是发言流。
- 右侧 3D 酒吧场景。
- 底部：投票按钮 + "加入辩论"输入框。

### 核心问题

1. **这是一个"辩论赛观看器"，不是辩论游戏**。AI 双方自动辩，玩家点点赞投投票。
2. **无胜负闭环**：辩了半天谁赢了？不知道。没有裁判、没有评委 AI、没有观众票选结果。
3. **玩家加入辩论是一次性的**：说一段就完了，没有"你的发言被对方反驳后你要不要回怼"的回合制对抗。
4. **无立场压力**：玩家可以随时换边，投票不影响任何东西，没有"押注/赌资"机制。

### 根因

- Orchestrator 的核心循环是"AI 轮流说话"，玩家交互是外挂在旁边的投票/插话。
- 缺少"裁判裁决"和"玩家作为辩手参与完整回合"这两层。

### 影响

- 玩家像在看两个 AI 拌嘴，自己是路人观众，没有代入感。

## 六、健身房场景诊断

### 现状（代码证据）

**`gym-orchestrator.ts`**：
- 极其薄。只有两个函数：
  - `startWorkout(plan)`：记录开始时间。
  - `tickWorkout()`：根据当前时间和计划计算"应该做了多少个 reps"。
- **没有 AI、没有 NPC 互动、没有对手**。orchestrator 里完全没有 LLM 调用。
- 动作计数是前端 `setInterval` 每 280ms 自动 +1（`GymShell.tsx` 里的 `useEffect` 计时器），时间每 1s +1。
- 玩家唯一操作：选择一个训练计划（如"俯卧撑 20 个"），点开始，然后看着数字自己涨。

**`GymShell.tsx` / `GymView.tsx`**：
- 左侧：训练计划列表（俯卧撑/深蹲/平板支撑等），选择一个开始。
- 中间：大数字显示 reps 和计时，自动跳动。
- 右侧：3D 健身房场景，几个 NPC 模型站着不动（不与玩家互动）。
- 完成后给一个"打卡成功"toast。

### 核心问题

1. **该场景尚未实现实质玩法**。这是一个伪装成 3D 场景的计时器 App。
2. **reps 是自动增长的**，玩家不需要做任何动作（连点击都不需要），数字自己涨。
3. **没有 NPC 教练**：教练角色不存在，没有动作指导、没有纠错、没有鼓励、没有"你再撑 5 秒"。
4. **没有社交/竞争**：没有和别人比谁举得重，没有排行榜，没有组队训练。
5. **3D 场景与玩法完全脱节**：右侧小人站着，和左侧计时器没有任何联动。

### 根因

- M5 阶段只做了 UI 壳和计时逻辑，AI 教练 / NPC 互动 / 挑战玩法完全没做。
- 产品定位模糊：到底是"自律打卡工具"还是"健身房社交游戏"？现在两者都不是。

### 影响

- 玩家进来后看数字自动跳 30 秒，觉得无聊退出。这是五个场景里完成度最低的。

## 七、图书馆场景诊断

### 现状（代码证据）

**`library-orchestrator.ts`**：
- 四个纯 LLM 函数：
  - `celebrityDeepChat()`：和名人多轮问答，注入 persona，回复 200-400 字。
  - `bookRecommendation()`：名人推荐一本书 + 理由（JSON）。
  - `bookClubOpening()`：名人读书会开场独白。
  - `librarianAnswer()`：AI 馆员按主题回答知识问题。
- **没有任何状态机、没有任务、没有评分、没有游戏循环**。全部是"用户问→AI 答"的单轮/多轮对话。
- 对话历史只保留最近 20 条（`slice(-20)`），关闭页面即丢失。

**`LibraryShell.tsx` / `LibraryView.tsx`**：
- 三个 Tab：名人读书会 / 深度问答 / AI 馆员。
- 左侧是聊天面板，右侧是 3D 阅览室（书架 + 桌椅 + 台灯 + 最多 3 个名人模型坐着）。
- 底部有"发布到广场"按钮（把一段回答/开场发到广场 feed）。
- WebSocket 同步其他读者的问答动态（`scene_event` 广播），但只是 feed 流，不能交互。

### 核心问题

1. **该场景本质是一个"名人 ChatGPT 聊天窗口"**，套了 3D 皮肤。
2. **零玩法结构**：没有任务、没有收集、没有挑战、没有进度。聊完就走。
3. **读书会是空壳**：点"开始读书会"→名人念一段开场白→然后呢？玩家可以继续提问，但没有结构化讨论环节（如"轮到你分享一个观点""其他读者怎么看"）。
4. **名人互动是通用聊天**：和名人聊任何话题都行，没有"这个名人会主动考你一个问题""和他对话需要达成某个目标"等设计。
5. **3D 阅览室是布景**：书架上的书不能取下来看，桌椅不能坐，台灯不能调。

### 根因

- 把"图书馆"这个主题直接翻译成了"知识库问答"，但没有想到"图书馆可以是一个有任务/收集/解谜的场所"。
- AI 能力被用来做问答，而不是做"有目标的互动"。

### 影响

- 好奇心驱使下聊一次有趣的名人对话，但没有理由再来第二次。留存极低。

## 八、跨场景共性问题总结

| # | 共性问题 | 代码证据 |
|---|---------|---------|
| 1 | **玩家被动观看 AI 表演** | Talkshow 自动演出、Werewolf AI 轮流发言、Bar AI 自动辩论、Gym 数字自动涨、Library AI 单向输出。玩家主动操作时间占比 <20%。 |
| 2 | **无清晰胜负/闭环** | Talkshow 无结局、Bar 无裁判、Gym 只是计时、Library 无目标。仅 Werewolf 有胜负判定。 |
| 3 | **无评分/反馈颗粒度** | 所有场景的反馈都是 toast / 文字 reaction，没有分数跳字、没有评级、没有"今日最佳"。 |
| 4 | **零重玩动机** | 每个场景玩一次后，第二次进来内容差不多（AI 重新生成随机文本），没有解锁、没有进度、没有赛季。 |
| 5 | **NPC 互动是通用聊天** | 所有名人 NPC 的互动都是"注入 persona → LLM 生成回复"，对话不影响游戏状态，没有关系度/好感度/任务链。 |
| 6 | **3D 场景与玩法脱节** | 五个建筑的 3D View 都是"布景"——模型站着/坐着，玩家不能走进去、不能和物件互动。真正的玩法全在左侧 2D 面板里。 |
| 7 | **场景间零联通** | 每个建筑是独立 Shell，有自己的 WebSocket room，自己的状态。玩家在健身房练的肌肉不能带到狼人杀里当"体力"，在图书馆读的书不能解锁广场上的书架。 |
| 8 | **无社交深度** | WebSocket 只同步位置和聊天文字，没有组队、没有协作、没有对战、没有围观。 |
| 9 | **上手到首个爽点过长** | 新用户进任意场景，平均需要点 3-5 次按钮、等 2-3 次 LLM 返回（每次 2-5 秒）才能得到第一次正反馈。 |
| 10 | **gameplay 模板太弱** | Scene Studio 的 collect/reach/quest 三种模板本质相同（走到→标记），UGC 创作者无法做出真正好玩的场景。 |

## 九、P0 重构方案（必须先做）

### P0-1：广场从"菜单"变成"有目标的世界"

**改哪些文件**：
- `Plaza3D.tsx`：新增广场物件系统、日常任务面板、玩家等级显示。
- 新建 `apps/web/src/plaza/PlazaObjectives.tsx`：日常任务 UI。
- 新建 `apps/api/src/plaza/plaza-routes.ts`：任务派发、进度上报、奖励发放。
- 扩展 `Plaza.tsx`（2D 兜底）：同步任务面板。

**核心逻辑变化**：
1. **日常任务系统**：每天 3 个任务，例如"去脱口秀讲一个笑话获得掌声""在狼人杀里活过 3 晚""在图书馆向一位名人提问"。任务目标内嵌到各场景完成后自动上报。
2. **广场物件**：在广场地面放置 3-5 个可交互物（如喷泉、公告栏、流浪 NPC、发光宝箱），走过去触发小事件（+经验、+金币、一段名人独白）。
3. **建筑状态角标**：每座建筑上方根据玩家进度显示——"未探索（新）"/"已完成今日任务（绿勾）"/"还差 1 步解锁（进度环）"。
4. **社交触发点**：广场上点其他玩家 avatar → 弹出"打招呼 / 组队 / 查看名片"。组队后两人可一同进入狼人杀/酒吧辩论。
5. **玩家等级**：所有场景行为累积经验，升级解锁广场装扮（avatar 外观）和新建筑内的特殊道具。

**预期体验**：玩家进广场不再是"点建筑"，而是"看今天要做什么→去完成→回来领奖"。

**复杂度**：中。需要新建 plaza-routes 和任务状态表，但各场景只需加一个"完成后 POST /api/plaza/objective"钩子。

### P0-2：场景工作室 gameplay 模板升级

**改哪些文件**：
- `apps/web/src/scene-studio/gameplay.ts`：扩展状态机。
- `apps/web/src/scene-studio/SceneRunner.tsx`：新增挑战交互。
- `apps/api/src/scene-studio/scene-planner.ts`：扩展 AI prompt 可生成新模板。
- `apps/api/src/scene-studio/scene-routes.ts`：新增游玩评分上报。

**核心逻辑变化**：
在现有 collect/reach/quest 之外，新增四种 gameplay 模板：

1. **`timed_collect`（限时收集）**：N 秒内收集 M 个物品，超时失败。状态机加 `timeLeft`、`failState`。
2. **`avoid`（躲避）**：场景中有巡逻的 NPC/障碍物，被碰到扣血，需从 A 走到 B。状态机加 `hp`、`hazardZones`。
3. **`npc_challenge`（NPC 挑战）**：NPC 出一道题/一个挑战（如"猜一个谜语""在 30 秒内回答三个问题"），玩家答对得分，答错 NPC 嘲讽。状态机加 `challengeResults`、`score`。
4. **`delivery`（配送/护送）**：携带一个物品从 A 走到 B，中途不能被障碍碰到，限时。

同时：
- 每次完成 collect/delivery 给分数（时间越短分越高），完成后展示"本次得分 / 历史最佳"。
- `scene-routes.ts` 新增 `POST /scenes/:id/play-result`，记录最佳分数，广场上展示热门场景排行榜。
- `scene-planner.ts` 的 system prompt 里让 AI 根据用户描述自动选择最合适的模板（而不是只会 collect）。

**预期体验**：UGC 创作者能做出"限时逃脱""NPC 问答挑战""护送任务"等真正有挑战的场景，玩家有重玩刷分动力。

**复杂度**：高。gameplay.ts 状态机要加分支（fail/retry/score），SceneRunner 要加计时器 UI 和碰撞伤害反馈。但模板是通用的，加一次所有场景都能用。

### P0-3：脱口秀——从"看演出"变成"开放麦之星"

**改哪些文件**：
- `apps/api/src/talkshow-orchestrator.ts`：重构核心循环。
- `apps/web/src/TalkshowShell.tsx`：重写主交互区。

**核心逻辑变化**：
1. **核心循环改为"玩家是演员"**：开场 15 秒 AI 主持热身 → 玩家上台连续讲 3 个笑话（每个笑话输入后 AI 观众实时评分：笑声分贝 0-100）→ 三个笑话平均分决定段位（冷场 / 尚可 / 炸场 / 今日之星）。
2. **玩家可以"互动砸挂"**：AI 讲笑话时，玩家可以选择"接梗/拆台/起哄"三个按钮之一，选对了（LLM 判断接得好）额外加分。
3. **反馈升级**：观众反应从文字变成可视化的"笑声分贝条"跳动 + 观众站立鼓掌特效（3D 场景里 avatar 站起来）。
4. **每日挑战**：今日主题（如"程序员笑话""约会糗事"），按主题讲笑话评分加成。

**预期体验**：玩家进来 30 秒内就上台讲第一个笑话，3 分钟内完成一轮得到评分。爽点=听到 AI 观众爆笑 + 上"今日开放麦榜"。

**复杂度**：中。orchestrator 已有 tellJoke 和 rating 逻辑，只需把"上台"从旁支变成主流程，加连续轮次和分数累积。

### P0-4：狼人杀——压缩等待时间，让玩家每回合都有事做

**改哪些文件**：
- `apps/api/src/werewolf-orchestrator.ts`：加速 AI 轮次，新增玩家主动动作。
- `apps/web/src/WerewolfShell.tsx`：新增快捷动作按钮。

**核心逻辑变化**：
1. **压缩 AI 发言**：AI 发言从每人 1 段长文改为每人 1-2 句短句，且多个 AI 可"同时"发言（日志并发滚动），把白天讨论从 3 分钟压到 60 秒。
2. **夜晚给好人任务**：夜晚不再干等，好人玩家可以"偷听"（小概率获取一条模糊信息）、"观察某人"（次日获得该人行为线索），让夜晚也有微操作。
3. **新增快捷动作牌**：玩家发言时不只是自由文本，可以选"跳预言家""查杀 X""带人上票"等动作按钮，系统自动生成对应话术并标记该动作为公开信息。
4. **本局评分**：结束后根据"是否准确验人/投票正确/生存天数"给表现分，累加到全局等级。

**预期体验**：玩家每分钟都有决策点，不再长时间盯着屏幕等 AI。

**复杂度**：中。orchestrator 状态机已存在，主要是节奏调整和动作牌 UI。

### P0-5：酒吧辩论——加裁判和胜负闭环

**改哪些文件**：
- `apps/api/src/bar-orchestrator.ts`：新增裁判裁决、玩家作为辩手的完整回合。
- `apps/web/src/BarShell.tsx`：新增回合结构和胜负展示。

**核心逻辑变化**：
1. **引入裁判 AI**（如请一位名人当裁判），辩论结束后裁判生成一段"谁赢了为什么"的裁决。
2. **玩家作为正式辩手加入一方**：不是说一句话就走，而是参与完整 3 回合（立论→对方反驳→你总结陈词）。每回合你发言后，对方 AI 必须回应你的具体论点（而不是自说自话）。
3. **押注机制**：辩论前玩家押一个"金币"在某一方，赢了翻倍。让投票有利益后果。
4. **胜负可视化**：条图显示双方论据强度（每回合根据发言质量 LLM 打分），结束后宣布胜方。

**预期体验**：玩家从观众变成辩手，有立场、有对抗、有输赢。

- `apps/web/src/GymShell.tsx`：重写交互。

**核心逻辑变化**：

**预期体验**：玩家有教练、有对手、有节奏感，不再是干等数字涨。

## 十二、设计共识落地检查

所有 P0 方案均遵循以下原则：
- **让玩家当主角、AI 当配角**：每个场景玩家主动操作时间占比 >60%。
- **30 秒能懂**：进场景后首屏就告诉你目标（"讲 3 个笑话赢掌声"/"活到最后"/"护送宝箱"）。
- **3 分钟一次正反馈**：每轮小循环 ≤3 分钟，必有分数/特效/奖励。
- **明确目标 + 有意义选择 + 可见后果 + 即时反馈**：每个场景都补齐这四要素。
