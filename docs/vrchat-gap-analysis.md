# 叽里呱啦 BalaBala vs VRChat —— 差距分析与补齐清单

> 分析方法：doubao-product-qa。基线来自对 `apps/api` / `apps/web` / `packages/shared` 真实源码的逐文件走查（6 场景编排器、人物解析、信令 WebSocket、空间音频、Avatar rig、场景工作室、新手引导、内容存储），对照 VRChat 公开产品形态。
> 范围：化身系统、社交体验、场景与内容、玩法深度、性能与稳定性、经济与留存、跨平台、内容安全与治理，共 8 个维度。
> 标注约定：**【已有但不够好】** = 功能存在、需加深；**【完全没有】** = 当前代码库零实现。
> 分支：`feat/round2-gameplay-revamp`。本轮已修复 1 个 tsc 报错（见文末）。

---

## 0. 一句话结论

BalaBala 在 **R2 玩法重做后，单人「AI 对手」玩法深度已经补上**（法庭出牌+天平、开放麦三维评分+callback、狼人杀动作牌、酒吧克制三角、健身房三关+AI 教练、图书馆知识擂台），**空间音频 / WebRTC 多人语音**也已具备 VRChat 级雏形。
但与 VRChat 的真正代差不在「好不好玩」，而在三件事：**① 真人多人社交是空的（所有场景都是 1 个真人 vs AI，没有好友/组队/同房间对战）；② 没有跨局留存经济（无全局等级/段位/每日挑战/排行榜/货币，一局结束即归零）；③ UGC 世界不可玩、不可被发现（场景工作室只有「走过去打卡」三种模板，发布后无评分/推荐/创作者激励）。**

## 1. 化身（Avatar）系统

| 项 | 现状 |
|---|---|
| BalaBala | 100 名人预置 3D 形象（20 位有全身模型+专属语音）+ 照片→3D（Tripo 实时建模）+ 自定义人物工作室。`avatar-rig.ts` 自动探测 blendshape/skeleton/procedural 三种模式，有 lip-sync、7 个固定表情（wave/nod/shake/point/clap/laugh/surprised，见 `EmoteType`）。 |
| VRChat | 用户上传自制 Unity/Blender 全身 avatar，全人形骨骼 IK、blendshape 表情、PhysBones（布料/头发物理）、手势/动画参数控制器、shader/材质切换、avatar 缩放；社区 avatar 数十万，可一键切换。 |

- **差距**：
  - 【已有但不够好】表情动作只有 7 个写死的 emoji，**没有自定义手势/动画控制器**，avatar 不能随玩家手部动作做手势。
  - 【已有但不够好】avatar 来源是「预置名人 + 照片生成」，**没有用户自由建模/换装/调材质/换色**的自定义面板（无 wardrobe、无颜色滑杆、无配饰挂载）。
  - 【完全没有】PhysBones/布料物理、avatar 参数化 toggles、mirror（镜子）。
  - 【完全没有】avatar 性能分级与「性能差 avatar 自动降级」（VRChat 的 avatar ranking）。
- **优先级**：P1（形象是社交产品的第一资产，但照片→3D 已是差异化亮点，不必照搬 Unity 上传）。
- **补齐动作**：
  1. 给现有 rig 增加「换装/配色」面板（衣服主色、肤色、配饰三档），用现成 GLB 材质换色即可，成本低。
  2. 把 7 个表情扩成 12~15 个，并支持「指向/挥手+语音」组合（emote 信令已有 `emote` 通道，扩枚举即可）。
  3. 加一面广场镜子（mirror），让玩家能看到自己 avatar——社交临场感性价比极高。

## 2. 社交体验（多人互动 / 语音 / 好友 / 活动）

| 项 | 现状 |
|---|---|
| BalaBala | WebRTC mesh 全互联（`useSpatialVoice.ts`），PannerNode HRTF + 反距离衰减 + 方位声像（`spatial-audio.ts`，19 个单测），WS 信令转发 rtc_sdp/rtc_ice/rtc_bye；广场 presence、`emote` 广播、文字 chat、user_vote。 |
| VRChat | 好友列表、邀请、收藏、组队 party、公开/私密实例、同房间 80+ 人、3D  proximity 语音常开、信任等级、世界内活动。 |

- **差距**：
  - 【已有但不够好】空间音频**已经做到 VRChat 水准**（距离衰减+方位），这是本项目最被低估的强项，应在产品宣传里前置。
  - 【完全没有】**好友系统**：无好友列表、无添加、无「谁在线」、无邀请。
  - 【完全没有】**组队/同房间真人共玩**：6 个场景全部是「1 真人 + N AI」。ws 虽然把房间做成了多人 presence，但玩法状态机没有第二个人类席位（法庭/狼人杀/酒吧都只有一个玩家 turn）。
  - 【完全没有】广场上点他人 avatar 出名片/打招呼/邀请同进（诊断文档 P0-1 已识别，未做）。
- **优先级**：**P0**（这是「3D 社交平台」与「单机 AI 游戏」的分水岭）。
- **补齐动作**：
  1. 先做最小好友环：广场点他人 avatar → 「加好友 / 邀请一起玩」，后端好友关系表 + WS 推送在线态。
  2. 选**狼人杀**作为第一个真人同场场景（它本来就有座位/投票/动作牌状态机，把「AI 补位」换成「真人座位」即可，改造量最小、社交张力最强）。
  3. 法庭/酒吧开放「旁听+实时投票」给真人旁观者（已有 `onlineCount`/vote 通道，放大展示即可）。

## 3. 场景与内容（场景数量 / UGC 工具 / 内容发现）

| 项 | 现状 |
|---|---|
| BalaBala | 6 个手工场景 + 自定义场景工作室：一句话→LLM 规划 `SceneSpec`→地形/植被/建筑/道具（Tripo 补模）→NPC 摆位→第三人称进入。gameplay 模板仅 `explore/collect/reach/quest`。 |
| VRChat | Unity SDK + Udon 可视化编程，用户可写出任意逻辑世界；公开世界数千个，有热门/更新/推荐流、世界评分、收藏。 |

- **差距**：
  - 【已有但不够好】**UGC 能造「布景」但造不出「游戏」**：三种模板本质都是「走过去→打勾」，无失败/计时/对抗/分数（诊断 P0-2 的 timed_collect/avoid/npc_challenge/delivery 四种新模板**未落地**）。
  - 【完全没有】**UGC 内容发现闭环**：`scene-routes.ts` 只有 generate/list/get/publish，**没有游玩记录、评分、点赞、热门榜**；发出去的世界无人可反馈、可被发现。
  - 【完全没有】类 Udon 的世界逻辑可编程性（短期不现实，但应作为长期方向）。
- **优先级**：**P0**（UGC 是「造物主」叙事的命脉，模板太弱会让创作生态空转）。
- **补齐动作**：
  1. 在 `gameplay.ts` 状态机加 `timed_collect`（限时+失败态）和 `npc_challenge`（NPC 出题+对错分）两种模板——比 avoid/delivery 简单，先这两个就能让作品有「重玩刷分」动机。
  2. 加 `POST /scenes/:id/play-result`（记录最佳分）+ 广场「热门场景」feed（复用现有 content likes 机制）。
  3. 发布页加「给别人玩」的预览二维码/链接，让 UGC 可外部分享。

## 4. 玩法深度（游戏机制 / 竞技 / 复玩动机）

| 项 | 现状（R2 后） |
|---|---|
| 法庭 | 预制牌 attack/evidence/mock/request_record + 每轮 2 弹药 + 天平 50:50 动态 + 对手短接茬 + 判决归因到玩家出牌高光（`court-orchestrator.ts`）。 |
| 脱口秀 | 选话题票→连续 3 段→punchline/pacing/resonance 三维评分→callback 关键词检测命中 +15→段位（冷场/尚可/炸场/今日之星）→金句卡。 |
| 狼人杀 | 角色狼/预/女巫 + 白天动作牌（跳预言家/指控/集结/辩护）+ 投票准确率评分 + recap。 |
| 酒吧 | 辩手 3 回合 + 数据/情感/逻辑角度克制三角 + 苏格拉底裁判裁决 + 强度条。 |
| 健身房 | AI 教练（3 persona）+ 节奏点击带练 + S/A/B/C 评级 + 90s 三关（反应/节奏/力量）+ 名人异步点评 + 连续打卡成就。 |
| 图书馆 | 领域选择题擂台（LLM 出题+本地兜底题库）+ 生命/连击/对手比分牌 + 名人深聊/读书会/馆员。 |

- **差距**：
  - 【已有但不够好】单局玩法**闭环已经成立**（有规则、有反馈、有结算），这是相对旧诊断的最大进步。
  - 【完全没有】**跨局复玩动机**：所有 session 是内存 Map/单局状态，结束后没有「段位上分」「连胜」「赛季」「再来一局比上局分高」的长期钩子。脱口秀/法庭/图书馆的分数**不沉淀**。
  - 【已有但不够好】对手是 AI，没有真人对抗的不确定感和社交张力。
- **优先级**：P1（单局已够好，缺的是把「单局爽感」接到「长期目标」上——见维度 6）。
- **补齐动作**：把每个场景的结算分（法庭天平胜方/开放麦段位/擂台正确率/健身房评级）上报到一个统一「战绩表」，哪怕先只做本地+本机排行。

## 5. 性能与稳定性（加载 / 帧率 / 崩溃）

| 项 | 现状 |
|---|---|
| BalaBala | Web Three.js + PWA；WebSocket 断线自动重连（`useReconnectingWebSocket`）；LLM 调用普遍带 retry+本地兜底（withRetry/withTimeout），单场景失败不崩；法庭 analyze 硬超时 38s 但有 quickStart 预置案跳过。 |
| VRChat | 原生 PC/Quest 客户端，avatar/世界性能分级、自动降级、对象池、实例分片。 |

- **差距**：
  - 【已有但不够好】容错做得不错（全链路 fallback），但**没有量化的加载/帧率/崩溃指标**——无埋点、无首帧耗时、无 FPS 监控。
  - 【已有但不够好】法庭首局 analyze 仍可能等 38s（虽有 3 个预置案可跳过，但默认入口仍慢）。
  - 【完全没有】avatar/场景性能分级与自动降级（低中端手机会吃力）。
- **优先级**：P2（web 端当前可接受，但要在用户量上来前先把指标埋上）。
- **补齐动作**：① 加首屏/进场景耗时 + FPS + 崩溃上报的最小埋点；② 把 analyze 第一帧（标题+双方姓名）先返回、KB 异步补（诊断 P0-5）。

## 6. 经济与留存（段位 / 成就 / 每日挑战 / 社交货币）

| 项 | 现状 |
|---|---|
| BalaBala | **代码库无全局 XP/等级/段位/每日挑战/赛季/排行榜/货币**。仅健身房有局部 streak 与成就（first_checkin/streak_3…），且不跨场景。广场 content feed 有点赞/评论（多为 seed 数据）。 |
| VRChat | 信任等级（Visitor→Trusted）作为软 progression、收藏夹、Plus 订阅、UGC 创作者激励。 |

- **差距**：
  - 【完全没有】**这是最大的留存空洞**。玩家在法庭赢了、开放麦炸场了、图书馆连胜了，退出后什么都不留下——没有「我是谁、我玩到哪了、明天为什么回来」。
  - 【完全没有】每日挑战 / 回归钩子 / 连续登录。
  - 【完全没有】可消费的软货币（买 avatar 装扮、场景道具）。
- **优先级**：**P0**（留存靠这个，且它是把维度 4 的单局爽感变现的那根管）。
- **补齐动作**：
  1. 新建一张 `player_profile`（userId → 全局 XP、等级、各场景胜场/最高分、连续天数），每个场景结算后一行上报。
  2. 广场建筑上挂「今日任务」（去开放麦讲一个段子 / 狼人杀活过 3 晚），完成发 XP。
  3. XP 升级解锁 avatar 配色/配饰（和维度 1 换装打通）。

## 7. 移动端 / 跨平台

| 项 | 现状 |
|---|---|
| BalaBala | Web PWA 可安装；`MobileControls.tsx` 触屏摇杆 + 陀螺仪判断；桌面 WASD。 |
| VRChat | PC VR、Quest 独立 VR、桌面模式——核心是 **VR 头显**。 |

- **差距**：
  - 【已有但不够好】触屏移动已有基础，但**各场景的密集按钮（法庭出牌坞、狼人杀动作牌）未针对小屏重排**。
  - 【完全没有 / 短期不追】VR 头显客户端。BalaBala 是浏览器 AI 原生路线，**不应硬追 VR**，但可把「移动端网页」体验做扎实作为差异化。
- **优先级**：P2。
- **补齐动作**：出牌坞/动作牌在竖屏改为底部大卡片（够拇指点）；PWA 加独立 manifest 图标与启动屏。

## 8. 内容安全与治理（对照 VRChat 信任体系）

| 项 | 现状 |
|---|---|
| BalaBala | LLM 输出有 system 约束（不碰隐私/家暴/自残、mock 越界词表扣分）；UGC 发布走 PublishForm。 |
| VRChat | 信任分级、avatar/世界举报与屏蔽、内容审核、年龄隔离。 |

- **差距**：
  - 【已有但不够好】LLM 侧有底线约束，但**真人 UGC 场景/真人聊天/真人语音没有任何举报/屏蔽/审核机制**。一旦开放真人多人（维度 2），这是必须同步上的红线。
- **优先级**：**P0（与真人多人同步上线）**。
- **补齐动作**：在开「好友/真人同场」前，先做一条最低限度：用户名片「举报/屏蔽」+ 语音一键静音。

## 9. Top 10 最该补的功能（按投入产出比 ROI 排序）

> 评分口径：收益（对留存/社交/差异化的拉动）÷ 改造量。排序尽量挑「复用现有通道、不重构场景」的高杠杆项。

| 排名 | 功能 | 解决哪个差距 | 状态 | 改造量 | ROI |
|---|---|---|---|---|---|
| **1** | **全局玩家档案 + XP + 等级 + 各场景战绩沉淀**（一张表 + 各场景结算上报钩子） | 维度 6 留存空洞 | 完全没有 | 小~中 | ★★★★★ |
| **2** | **广场每日任务（3 个/天）+ 建筑状态角标**，回报到 #1 的 XP | 维度 6 + 广场无目标 | 完全没有 | 小 | ★★★★★ |
| **3** | **狼人杀开放真人同场（AI 补位换真人座位）** | 维度 2 社交空转 | 状态机已有，换席位 | 中 | ★★★★★ |
| **4** | **好友列表 + 广场点头像「加好友/邀请同玩」+ 在线态** | 维度 2 | 完全没有 | 中 | ★★★★☆ |
| **5** | **UGC 场景加 `timed_collect` + `npc_challenge` 两种可玩模板** | 维度 3 创作生态空转 | 状态机加分支 | 中 | ★★★★☆ |
| **6** | **UGC 世界发布后可被发现：游玩记录 + 评分 + 广场热门 feed** | 维度 3 内容发现 | 复用 content likes | 小 | ★★★★☆ |
| **7** | **avatar 换装/配色面板 + 广场一面镜子** | 维度 1 形象资产 | 已有 rig，换材质 | 小 | ★★★★☆ |
| **8** | **首屏/进场景耗时 + FPS + 崩溃最小埋点** | 维度 5 性能不可见 | 完全没有 | 小 | ★★★☆☆ |
| **9** | **真人语音/聊天的「举报/屏蔽/静音」三件套**（与 #3/#4 同步上） | 维度 8 安全红线 | 完全没有 | 小 | ★★★☆☆（红线，必须做） |
| **10** | **法庭 analyze 首帧即返 + 砍 Analyzing 假动画**，30s 内出第一个决策点 | 维度 5 上手等待 | 已有 quickStart 兜底 | 小 | ★★★☆☆ |

**不建议现在做**（ROI 低或方向不符）：VR 头显客户端、类 Udon 世界可视化编程、PhysBones 布料物理、Unity avatar 上传生态——这些是 VRChat 的重资产路线，BalaBala 的差异化在「AI 原生 + 浏览器即点即玩 + 名人 NPC」，应把工程集中在「真人社交闭环 + 留存经济 + UGC 可玩」三件事上。
